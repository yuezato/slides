④ 否定を入れる — まず、素朴にやると失敗する

③ の ?←(ab) を !←(ab) に変えるだけで、Horn の単調性が壊れる

節はたった 1 箇所しか変わりません: m@i ← x@i, y@i が m@i ← ¬x@i, y@i になる。
何が壊れるか
Horn の伝播は単調で、事実は増える一方です。¬x@i を「今 x@i の証明がない」と読むと、後から x@i が導出された瞬間にその発火が嘘になる。
③ の表で実際に起きること
ステップ 1 の時点では x@2 はまだ U。ここで ¬x@2 を真として発火させると m@2 が出る。
ところがステップ 2 で x@2 = T になる。
答えが伝播の順序に依存してしまう。
もっと悪い場合
p@i ← ¬q@i     q@i ← ¬p@i
どの順序でも一貫した答えがない。これは意味論の問題であって、実装の問題ではない。
解決 — 読んでよい失敗と、読んではいけない失敗を分ける
そのために要るのが rank map
否定の中身を厳密に下位の world に置く (q → ¬r ⟹ β(r) < β(q))。下から順に、飽和 → 閉包 → 上へ、と進めば、⇑ は必ず閉じた表からしか読まれない。

④ stratified negation — 走る例

③ の ?← を !← に変え、外側にもう一段の否定を被せる

これが論文の走る例。語は w = abac のままです。
Eex  =  !→( a  !←(ab)  ?→(b∪c) )  any
? = 肯定、! = 否定、→ = lookahead、← = lookbehind。すべて zero-width。
内側 Einn = a !←(ab) ?→(b∪c) を w = abac 上で走らせる
a1b2a3c4
  • 位置 3: a を読んで 4 へ。4 で終わる文字列は ac ≠ ab なので !←(ab) は成功。w[4]=c ∈ {b,c} で ?→ も成功。
  • 位置 1: 4 と同様に進むが、2 で終わる文字列が ab なので否定 lookbehind が失敗。
  • 位置 2, 4: 先頭の a で即失敗。
結論

Einn が成功するのは 位置 3 だけ。
よって外側の !→(Einn) は {1, 2, 4} で成功し、
Eex 全体は 1, 2, 4 でマッチ、3 で失敗。

この「位置 3 だけが落ちる」という一点を、
以降すべての表現(自動機・Horn・表)で再現します。
※ 本論文の lookbehind は、起動位置 p を含めて左へ読む向き付き規約
(§3.4)。上の「4 で終わる文字列 = w[3]w[4]」はその規約です。

四段のまとめ — 状態の直感

「そこから受理に入れるか」— 形はそれで正しい。三つだけ補正が要る

論文の定義 (§3.3) — ①〜④ を通じて一度も変わらなかったもの

q@i ⇓  ⟺  配置 (q, i) が有限の受理計算をもつ。
acceptance relation は、対応する Horn プログラムの最小不動点そのもの。

  • run ではなく run tree。 ∧ があるので「一本の道」ではない。∨・遷移は ∃(一本)、∧ は ∀(両方)、⊤ が葉。→ ③ の m@2 で見たところ。
  • 有限性が効く (lfp であって gfp ではない)。 two-way なのでヘッドが往復して無限に続く「run」が作れるが、それは失敗。→ ②b の p@1 ⇄ q@2 がまさにこれ。
  • 否定辺の先は「まだ証明が無い」ではない。 q → ¬r が読むのは □(r@i = fail)、つまり下位 world の lfp が確定した後の failure。→ ④ の閉包 (3) と (5)、そして Δ2 の world 一つずつ。
言い換えるなら

q@i ⇓ = 「(q,i) から有限の受理 run tree が存在する」
— 下位 stratum の否定は既に確定した oracle として読んでよい、という条件つきで。

ここが後で効く
この後 FHCM に上げると、直感は ∃(どれかの run) から
優先順位で選ばれた唯一の run に変わります (Δ1)。
聞き手はここで直感を持ち越しがちなので、明示的に切り替えを宣言するとよい。

Δ1 — 真偽値から終点値へ

セルが「成功したか」ではなく「どこで終わったか」を持つ

JavaScript の matcher も PEG も、返すのは真偽値ではなく優先順位で選ばれた一つの終点。
セルの値域
Cell(I) = {unknown} + {fail} + {ok(j) | j ∈ I}
情報の増加は unknown → (fail または ok(j)) の一段だけ。
相異なる最終値の間に順序は無い (flat domain)。
functional であること
R@i ⇓ j  ∧  R@i ⇓ j′  ⟹  j = j′
packrat parsing の「memo 1 エントリにつき結果 1 つ」そのもの。
Boolean 行はこの特殊ケース: q@i は q@i ⇓ i の略記 (対角)。
PEG の 2 規則が、そのまま FHCM の規則になる
P@i ⇓ j    Q@j ⇓ k
(P Q)@i ⇓ k
Seq
P@i ⇓ j
(P/Q)@i ⇓ j
Left
P@i ⇑    Q@i ⇓ j
(P/Q)@i ⇓ k
Right
対称性が壊れている

肯定の事実 R@i ⇓ j は導出された瞬間に使える。
失敗 R@i ⇑ は □(R@i = fail) の略記で、閉じた世界からしか読めない。

ordered choice の右枝は「左枝がまだ成功していない」では発火できない。
「左枝がもう成功しないと確定した」でなければならない。
